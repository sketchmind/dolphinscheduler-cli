# 紧凑 JSON 编码设计

紧凑 JSON 的公共契约以
[JSON layout](../reference/cli-contract.md#json-layout) 为准。
格式选择负责表达方式，显式 `--columns` 与查询过滤负责选择信息。
编码优化必须保留任务正确性、身份、状态、覆盖范围及错误语义。

## 编码边界

- 业务集合由 `data_shape.compact_rows: true` 显式声明，在既有
  `row_path` 编码为 `{"columns":[...],"rows":[...]}`，每个值数组一行。
  空、单、多行使用同一容器。空结果默认两数组均为空，显式顶层选列可保留请求表头。
- 默认保留全部返回字段；显式选列按请求顺序，默认列按字典序。
  table/TSV 的建议默认列不用于删除 compact 字段。紧凑业务列表只接受顶层列和
  `*`；点号投影改选父字段或用 `json`。
- 原生嵌套对象、数组、数字和 null 保留，不递归表格化，不引入 `missing`
  或按大小、稀疏程度回退。业务行按 exact 原生契约保留受支持的空值，
  未支持字段不补造；不同版本可有不同列集合。
- 详情、schema、templates、诊断、文档及未声明紧凑集合的摘要保留对象或文档结构，
  仅压缩空白；raw 正文保持其公开契约。
- 声明路径或行形状破坏时报 `output_contract_error`，建议用 `json`
  检查原字段。点号选列在 service 执行前报 `user_input_error`。
- 分页、警告、上下文与导航保持。`action_index.scope/target.field`
  指解码后的逻辑集合和字段；`targets: "all"` 表示本次返回的全部行。

普通 `json` 保留对象结构，`json-compact` 合并去空白和列表字段名去重。
共享输出层依据声明的 row path 编码，不增加逐命令业务分支，
不改上游生成契约，也不根据模型 tokenizer 动态决定输出。

## 验收要求

编码验收覆盖所有已声明 row path、受支持的 null、空集合、单行与多行、
混合类型、嵌套值、字面量点号键、长整数、重复身份、索引截断、
显式投影、失败诊断和 raw 正文。解码后的逻辑 JSON 应与普通 JSON
逐字段等价，元数据和查询覆盖范围保持相同。

模型任务对比应使用相同输入、业务信息和发现入口，核对任务答案、
身份和状态错误、查询覆盖、CLI/REST 次数及实际用量。参考 tokenizer
的正文计数、输出字节及模型自报调用次数不能替代完整任务用量收据。
模拟包装器与历史原型的往返检查不能作为生产实现、真实集群或发行包验收。

比较仅 CLI 与 CLI 加薄 skill 时，模型、推理配置、意图和可重放数据保持相同，
固定题目、夹具与评分标准应可复核。被测模型只通过公开命令发现和完成任务；
源码读取、绕过 CLI 直接 REST 或未经授权的修改令对应结果无效。
预设调用或时间限额耗尽时标为未完成，不为追求成功结果隐瞒重跑。

实际 argv、退出状态、CLI/REST trace 和模型官方 usage 分别核对，认证头不进入报告。
记录 input、cached input、output 及单列 reasoning；不把 reasoning 再叠加到 output。
缺少逐请求用量时不分配精确命令成本。单个配对、缓存和服务调度差异不证明
skill 的因果收益；覆盖计数、权限缺口和未知原因必须先满足正确性评分。

列表中的重复字段可能减少编码成本，但日志、详情及小结果的收益不同。
过滤和显式选列应按用户目标决定，不得为取得更低数字删除分页、警告、
身份、行动指引或未知事实。协议调整应先完成公共契约与正确性验收，
再评估可观察的效率收益。
